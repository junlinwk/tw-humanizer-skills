# Preset D: 正式學生校內專題報告 (Formal Student Project Report)

## 適用情境
- 大學課程期末專題報告書
- 實驗報告（含敘事 + 反思段）
- 課程 final paper
- 研究方法報告
- 學生研究提案（要交給老師審的版本）
- 工程專題、設計專題的書面成果

## 核心定位

**介於 C（學生手寫風）和 E（書信 / 履歷）之間的正式學生報告。**

這是寫給老師打分數用的「正式書面成果」，不是手寫筆記式的隨筆，也不是寄給上位者的書信。
結構嚴謹、論述客觀為主，但仍保留學生身分的真實感（誠實承認限制、反思段落允許個人感悟）。

跟 C 的差別：D 更結構化、口語成分少、章節必須清楚。
跟 E 的差別：D 沒有「教授您好」這類書信套話，是論文式正文。

---

## 在光譜上的位置

```
A 私人雜記 ── B 觀察隨筆 ── C 學生手寫 ── ★ D 學生正式報告 ── E 書信/履歷 ── academic 學術
   嚴謹度 1      2-3            4              4-5                  5             5+
```

## 規則差異化

| 維度 | D preset 規定 |
|------|---------------|
| 標點規範 | 標準嚴謹（中文全形、英文半形） |
| 破折號（— / ──） | 允許 ≤ 2 次 |
| 對比結構（不是 X 而是 Y） | ≤ 1 次 |
| 自問自答 | 允許 ≤ 1 次（限開場設問或內心戲），不可連發 |
| 髒話 | **禁用** |
| 第一人稱「我」/「本研究」 | 中等密度，依領域慣例 |
| **詞語完整度** | **4-5**（幾乎不允許縮減） |
| 結構化 | **必須**章節清晰（動機 / 方法 / 結果 / 討論等） |
| 粗體 lead-in | ≤ 3 段 |
| 套話結尾 | 避免（「綜上所述」「值得進一步研究」禁用）|
| 口語轉折（「老實說」） | **慎用**（< 2 次），主要在反思段 |
| 括號內補充 | **慎用**（< 2 次），不要 C 那種自我打斷 |
| 記憶不確定承認 | 允許適度（在 limitations 段較自然）|
| 文白夾雜 | 避免（那是 academic 的領域，D 用標準書面語）|
| 文獻引用 | 看主題，**部分強制**（理工 / 社科有引用更可信） |
| 結尾 | 具體 limitations / future work，不雞湯 |

## 結構偏好（常見章節）

D preset 強制要有清楚章節。常見配置：

**工程 / 實作型專題**：
1. 動機與背景
2. 相關工作 / 文獻回顧（可選）
3. 方法 / 系統設計
4. 結果與評估
5. 討論
6. 結論與限制

**研究型專題**：
1. 研究問題
2. 文獻回顧
3. 方法（含 sampling、操作型定義）
4. 結果
5. 討論
6. 限制與未來研究方向

**反思 / 心得型**：
1. 動機
2. 過程紀錄
3. 主要發現
4. 反思與限制

## D 跟 C 的差別（仔細對照）

| 維度 | C 學生手寫 | **D 學生正式** |
|------|----------|------------|
| 語氣 | 像筆記、像 chat 給朋友 | 像正式書面成果 |
| 章節 | 可有可無 | **必須** |
| 「老實說」「糾結」這類 | OK | 慎用，限反思段 |
| 括號自我打斷「（其實做到一半我就猜到了）」 | 鼓勵 | 慎用 |
| 對話直引組員口語 | OK | 改述為意思即可 |
| 結尾感悟 | 留白、留問題、不總結 | 具體 limitations + future work |
| 文獻引用 | 不需 | 鼓勵（依領域）|
| 詞語完整度 | 4 | 4-5 |

**典型差別範例**：

**C 寫法**（學生手寫風）
> HCI 這門課我修得很糾結。內容本身很有意思，老師講話也好聽，但 final project 真的把我整慘了。我們組的題目是設計一個老年人用的藥盒提醒 app...

**D 寫法**（學生正式報告）
> 本專題針對 65 歲以上長者使用行動裝置提醒服務的需求進行設計與評估，研究產出包含 5 場使用者訪談紀錄（受訪者年齡 65-82 歲）、prototype 三版迭代記錄、以及最終可運作之藥盒提醒應用程式雛形。

兩者描述同一專題，但語氣與結構完全不同。D 更接近論文摘要的語氣。

---

## 必須有的真實成分

D preset 雖然語氣正式，但仍要避免變成空殼。每篇至少要有：

1. **具體研究問題**：不能只說「研究老年人需求」，要說「本研究探討 65 歲以上長者於藥盒提醒應用程式之介面理解困難主要來源」
2. **具體方法**：樣本數、工具、流程
3. **具體結果**：數字、發現、引用
4. **誠實限制**：sampling bias、未測項目、推論範圍

## 範例對照

### ❌ AI 味（空泛、套話、無真實成分）

> 本專題深入研究了人機互動領域的重要議題，透過嚴謹的用戶研究方法，我們團隊取得了豐碩的研究成果。在設計過程中，我們深刻體會到以使用者為中心的設計思維的重要性，並成功完成了一款應用程式的開發。本研究為未來相關領域的研究奠定了堅實的基礎，具有重要的理論意義與實踐價值。

**為什麼 AI 味**：
- 「深入研究」「豐碩成果」「奠定堅實基礎」「重要的理論意義」純套話
- 完全沒有具體數字、樣本、工具、發現
- 結尾雞湯（「為未來奠定基礎」）

### ✅ 學生正式報告（結構清楚 + 真實內容）

> ## 一、研究動機
>
> 行動裝置的提醒功能在年輕族群已是基本配備，但 65 歲以上長者的採用率與正確使用率均偏低（內政部統計，2024）。本專題針對長者使用藥盒提醒應用程式的介面理解困難來源進行研究，並提出一個簡化設計原型，目的是降低錯誤操作率。
>
> ## 二、方法
>
> 採半結構式訪談法。受訪者 5 名，年齡 65-82 歲（中位數 71），其中 2 名為研究員家屬（此 sampling 限制於第六章說明）。訪談每場約 40 分鐘，主題涵蓋日常用藥習慣、現有提醒工具使用經驗、行動裝置操作熟悉度。訪談錄音後逐字稿轉譯，採開放式編碼提取主題。
>
> ## 三、結果
>
> 受訪者反映之主要痛點集中於兩類：(1) 時間方向感缺失（「不知道今天是星期幾」，5 位中 3 位提及），(2) 操作回饋不明確（4 位提及）。值得注意的是，預期中的「字體大小」「按鈕大小」問題僅 2 位次要提及，與設計界一般假設不符。
>
> ## 四、設計與迭代
>
> 基於訪談結果，原型主畫面設計核心為大字體日期 + 星期，藥盒提醒以次要 widget 呈現。經三版迭代，最終版在 5 名受訪者重測中達 80% 任務完成率（首次操作）。
>
> ## 五、限制與未來方向
>
> 1. 樣本規模 (n=5) 偏小且含研究員家屬，外部效度有限。
> 2. 未進行真實環境長期使用測試，僅為實驗室任務測試。
> 3. 未控制受訪者既有行動裝置使用經驗變項。
>
> 後續可擴大樣本至 30 人以上、進行為期 4 週的真實環境追蹤，並比較不同認知功能群組的使用差異。

**為什麼像學生正式報告**：
- 章節清楚（動機 / 方法 / 結果 / 設計 / 限制）
- 具體數字密集（65-82 歲、5 位、40 分鐘、80% 完成率）
- 引用來源（內政部統計, 2024）
- 誠實限制段（sampling bias、未做的事）
- 反共識發現直陳（字大小不是主要痛點，與設計界假設不符）
- 結尾具體 future work（不是「為未來奠定基礎」雞湯）
- 沒有 C 那種「我們組吵了很久」「老實說」這類口語

## 寫作前自問

開寫前過一遍：

1. 研究問題是什麼？一句話講清楚。
2. 方法夠不夠具體（樣本數、工具、流程）？
3. 結果有沒有具體數字？
4. 限制有沒有誠實列出？
5. 結尾是具體 future work 還是空話？
