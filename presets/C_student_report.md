# Preset C: 學生手寫風報告 (Student Handwritten-Style Report)

## 適用情境
- 修課動機書、課程心得
- 期初報告（非正式版）
- 學期反思 / 課程心得
- 實驗報告的敘事 / 反思段（非純數據段）
- 個人化的非正式期末報告
- 寫給自己整理用的學生隨筆型紀錄

## 核心定位

**手寫風學生報告：結構鬆散但有人味。**

這是「學生在筆記本上整理思路，再打字成文」的感覺。
不是企業簡報、不是公務員文件、不是論文摘要。
允許括號補充、不確定承認、口語轉折、踩坑紀錄。

跟 **D（學生正式校內專題報告）** 的最大差別：D 是要交給老師打分數的正式書面成果，章節嚴謹；C 是學生自己的書寫，比較鬆。

---

## 在光譜上的位置

```
A 私人雜記 ── B 觀察隨筆 ── ★ C 學生手寫 ── D 學生正式報告 ── E 書信/履歷
  嚴謹度 1      2-3              4              4-5                  5
```

- 比 B 有結構（章節 OK）但比 D 鬆
- 比 D 少正式感（允許口語、可以沒章節）
- 比 E 多人味（不需要套話、不需要書信體）

## 規則差異化

| 維度 | C preset 規定 |
|------|---------------|
| 標點規範 | 標準（中文全形、英文半形） |
| 破折號（— / ──） | 允許 ≤ 2 次，慎用 |
| 對比結構（不是 X 而是 Y） | ≤ 1 次 |
| 自問自答 | 允許 ≤ 1 次（開場設問或內心戲），不可連發 |
| 髒話 | 避免；「踩坑」「卡關」「煩死」輕度抱怨 OK，不刻意加 |
| 第一人稱「我」 | **必須**（密度中高） |
| **詞語完整度** | **4**（偶有縮減，主要在反思 / 感受段）|
| 結構化 | 允許章節、編號；粗體 lead-in ≤ 3 段 |
| 三點並列 | 不強迫每段三點，混用 2/4/5 |
| 套話結尾 | 避免（「綜上所述」「值得注意」「賦能」這類禁用） |

| 文白夾雜 | 避免（這是 academic 的領域） |
| 文獻引用 | 看主題需要，不強制 |

## 「手寫風」五大訊號（C preset 的核心）

這幾個是 humanize skill 累積識別出的「真實學生寫作」訊號。C preset 鼓勵主動使用。

### 1. 括號內補充 / 自我打斷

學生筆記常有「寫到一半補一下」的痕跡。打字版用括號還原：

- 「⋯這個方法後來證明不行（其實做到一半我就猜到了，但還是想試）⋯」
- 「⋯參考了 Nielsen & Chuang（書名我一開始忘了，回去翻書才查到）⋯」
- 「⋯（補一下背景：上面這段我重寫過兩次，第一版邏輯有漏洞）⋯」

這是 AI 不會做的事，**強烈人類訊號**。

### 2. 記憶不確定承認

不要假裝什麼都記得清楚。

- 「實驗大概在 11 月初進行，確切日期我忘了，可能是第二週」
- 「老師講過一個比喻，原話想不起來，意思大概是⋯」
- 「那篇論文我印象是 Karp 寫的，年份應該是 1970 年代」

人類會說「忘了」「印象大概」「不確定」，AI 預設會編造或避開。

### 3. 學生視角承認

學生就是學生，不要裝懂。對應 universal.md 第 0 條「不知道直接說」。

- 「我承認這部分我還沒完全理解」
- 「老師上課時我有點跟不上，下面這段是我自己看書補的，不確定對不對」
- 「這部分如果有錯歡迎老師指正」
- 「我目前的理解是 X，但 Y 可能也說得通」

### 4. 自然口語轉折

避免企業簡報式的「綜上所述」「值得注意」。

允許：
- 「老實說⋯」
- 「不過後來想了想⋯」
- 「補一下背景⋯」
- 「岔題一下，這部分讓我想到⋯」

「總而言之」**僅在**接具體前文回扣時 OK（不可作為空話結尾收場）。

### 5. 具體踩坑紀錄

寫過程要寫真實的卡關，不要美化成順利完成。

- 「第一次跑出來結果完全是錯的，後來才發現是 normalization 沒做」
- 「我以為改 X 參數就會 work，結果跑了三天才發現問題在 Y」
- 「Arduino 那個專題我接錯腳位 30 分鐘才發現」

## 必須有的真實成分

每篇 D 報告至少要有：

1. **具體動機**：為什麼選這題（不能只是「有興趣」）
2. **具體過程**：做了什麼（工具、版本、步驟）+ 卡在哪 + 怎麼解
3. **具體結果**：數字、圖、實作（不要「結果很好」這種空話）
4. **誠實反思**：學到什麼具體的東西 + 什麼還沒搞懂 + 限制

每段至少 1-2 個具體錨點：時間、地點、人名、工具名、版本號、數字、引用。

---

## 結構偏好（典型五節，依需求挑選）

學生報告書常見結構：

- 一、為什麼做這題（動機 + 個人理由）
- 二、做了什麼（過程 + 卡關 + 解法）
- 三、結果與發現
- 四、反思與限制
- 五、（可選）未來想做的延伸 / 未解問題

允許小節之間有過渡段，不要硬切。不強制每篇都用這個結構。

## 範例對照

### ❌ AI 味（過度結構、空泛、套話結尾）

> 本報告針對人機互動課程的期末專題進行回顧。我們團隊深入研究了老年人使用行動裝置的痛點，並設計了一款藥盒提醒應用程式。透過用戶研究、原型設計、迭代測試三個階段，我們團隊取得了豐碩的成果。這次經驗讓我深刻體會到使用者中心設計的重要性，為我未來的職涯發展打下了堅實基礎。

**為什麼 AI 味**：
- 「深入研究」「豐碩的成果」「打下堅實基礎」抽象空話
- 工整的「三個階段」三點論
- 結尾雞湯（為未來職涯打下基礎）
- 零具體數字、零踩坑、零個人語氣

### ✅ 學生手寫風（有結構也有人味）

> ## 一、為什麼做這題
>
> 期初老師讓我們從三個題目挑一個，我選了「老年人使用行動裝置」這題。老實說選這題的理由蠻單純的：我阿嬤上個月剛換智慧手機，第一週每天打給我問怎麼用。我當時很想幫她但不知道從哪幫起，剛好這題能讓我系統地搞清楚。
>
> ## 二、做了什麼
>
> 第一階段是 user interview，原本計畫做 8 人但只約到 5 個（其中兩個是同學的長輩，這部分我承認 sampling 有 bias）。受訪者年齡 65-82。
>
> 訪談結果跟我預期差很多。我以為大家會抱怨「字太小」「按鈕太小」這種視覺問題，結果 5 個人裡有 3 個明確說「字大小沒問題」。他們真正的痛點是「不知道今天是星期幾」（藥盒一週一格但他們搞不清楚今天在第幾格）。這個 finding 直接改變我們的設計方向，後來主畫面變成大字體的日期 + 星期，藥盒提醒反而是次要。
>
> 第二階段做 prototype 我們吵了很久。組員 A 想加語音輸入，我覺得長輩根本不會用，最後折衷做了一個「按一下就跳到下一個」的簡化版。期末展前一晚我們 4 個在實驗室通宵改到清晨四點，我跟組員說「這版我還是覺得有問題」，他白了我一眼說「拜託先過明天再說」。
>
> ## 三、結果
>
> 期末 demo 老師給我們 A-。看到分數那刻，我腦中浮現的居然是訪談時那個 82 歲爺爺說的話：「我女兒每次回來都會幫我貼便利貼，但便利貼會被風吹掉。」這句話我寫進報告好幾次都覺得寫不好，最後乾脆直接引用。分數本身反而沒留下太多印象。
>
> ## 四、反思
>
> 這次最大的學習是「用戶說的痛點不一定是真正的痛點」。我們前期花太多時間想設計，太少時間做訪談，後來才發現真正影響設計方向的是訪談那一句話。如果重來一次，我會把訪談時間從 1 週拉長到 3 週。
>
> 還沒解的問題：我們的 prototype 沒做完整的 usability test（只有 demo 給老師看）。真的給長輩用會不會 work，我不確定。

**為什麼像人寫**：
- 動機具體（阿嬤換手機這件具體事）
- 數字具體（5/8 受訪者、65-82 歲、A- 成績、4 人通宵到清晨四點）
- 承認限制（sampling bias、未做 usability test）
- 真實踩坑（吵架、通宵、第一版有問題）
- 對話直引（組員 + 爺爺）
- 結尾不雞湯（留未解問題）
- 不誇大成果

## 與其他 preset 的差別

| 維度 | **C 學生手寫** | D 學生正式報告 | E 制式申請文 | academic 學術 |
|------|-------------|------------|----------|------------|
| 結構章節 | 可有可無 | **必須** | 章節 + 目錄 | 章節 + 小節 + 附錄 |
| 口語轉折「老實說」 | OK | 慎用 | 禁 | 禁 |
| 括號自我打斷 | **鼓勵** | 慎用 | 不需 | 改為 footnote |
| 個人情緒 | 適度鼓勵 | 收斂於反思段 | 節制 | 中性 |
| 套話密度 | 低 | 低 | 高（敬祝教安） | 中（學術慣用） |
| 文獻引用 | 不需要 | 看主題 | 不需要 | **必須** |
| 文白夾雜 | 避免 | 避免 | 避免 | 允許 |
| 詞語完整度 | 4 | 4-5 | 5 | 5+ |
| 自稱 | 我 | 我 / 本研究 | 我 | 學生 / 筆者 / 本研究 |
| 對讀者口吻 | 平等對話感 | 對老師回報 | 對上位者書信 | 學術中性 |

## 寫作前自問

開寫前過一遍這五題：

1. 為什麼選這題？理由具體到可以說給朋友聽。
2. 過程中真的卡過哪些坑？挑 2-3 個寫進去。
3. 有沒有什麼意外發現？跟原本預期不同的部分？（最有人味的通常在這）
4. 哪些我還沒完全懂？哪些做得不夠好？誠實承認。
5. 結尾要留未解問題還是具體下一步？不要套話。

## 套用 humanize 通用層的自審清單

寫完後對照 `core/universal.md` + `core/lang_zh.md` 跑一遍：

- [ ] 第 0 條：不確定的事實有沒有誠實標出？
- [ ] 自問自答 ≤ 1 次（且為開場設問或內心戲）
- [ ] 「不是 X，而是 Y」≤ 1 次
- [ ] 沒有「綜上所述、值得注意、與此同時、賦能、深度整合」這類詞
- [ ] 沒有「在當今 X 的時代背景下」「隨著 X 的快速發展」
- [ ] 沒有空泛形容詞堆疊（強大、優秀、卓越、全面、深刻）
- [ ] em dash 全篇 ≤ 2 個
- [ ] 三點並列段落 ≤ 2 處
- [ ] 第一人稱「我」出現 ≥ 5 次
- [ ] 「的」字密度沒有單句 > 3 次
- [ ] 至少 1 處「手寫風訊號」（括號補充 / 記憶不確定 / 踩坑紀錄 / 口語轉折 / 學生視角承認）
- [ ] 結尾不是雞湯（不是「為未來打下基礎」「期許自己更上一層樓」這類）
- [ ] 中段過渡用的「總而言之」/「綜上所述」有具體前文回扣（如有用）

通過 ≥ 11 項才算合格。
