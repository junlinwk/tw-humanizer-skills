# 紀錄協議 (Notes Protocol)

每個語境有 `notes.md`，記錄用戶在該語境下的小偏好與習慣。
AI 在互動後可更新此檔，下次相同語境互動前先閱讀。

---

## 核心原則

1. **最小紀錄**：每條 < 1 行，極致核心摘要
2. **分門別類**：依該語境的分類欄位寫
3. **不重複**：已存在的觀察不要重寫
4. **過期濃縮（不刪除）**：超過 1 個月的細節事件 → 濃縮成模式描述。**保留資訊，捨棄細節**。
5. **機密敏感**：用戶明確要求別記的不要記
6. **不要寫進過度詳細**：細節讓 AI 在當下對話判斷，notes.md 只給脈絡

---

## 各語境紀錄重點

| # | 語境 | 紀錄內容 |
|---|------|---------|
| 1 | 閒聊 | 聊過的話題、共同梗 |
| 2 | 情緒 | 用戶情感模式、近期事件、什麼能緩和 |
| 3 | 求助 | 用戶踩過的坑、環境設定、工具偏好 |
| 4 | 討論 | 討論過的主題標題（極簡） |
| 5 | 正式 | 用戶身份背景、寫作目的、文體偏好 |
| 6 | 親密 | 用戶喜好、反饋觀察 |
| 7 | 衝突 | **AI 自己的錯誤模式**、用戶不耐煩訊號、緩和方式 |
| 8 | 創作 | 寫作風格偏好、過去產出反饋 |
| 9 | 教學 | 用戶水平、教過什麼、卡點、學習偏好 |

---

## 紀錄時機

- 對話結束時
- 換語境時
- 觀察到新模式時
- 用戶明確說「記住 X」時
- **特別重要**：AI 在 7 衝突 中發現自己的錯誤後，必須記到 `7_conflict/notes.md`

## 閱讀時機

- 進入該語境前（必讀）
- 不確定如何回應時
- 用戶疑似不耐煩時 → 優先讀 `7_conflict/notes.md`
- 教學 / 求助 / 創作互動前 → 讀對應 notes 確認用戶水平與偏好

---

## 紀錄量上限

- 每個 `notes.md` 建議 ≤ 50 行
- 超過時觸發**濃縮**（不是刪除）：
  - 合併相近條目成一條模式描述
  - 細節事件 → 變成模式 / 類別摘要
  - 多條同類踩坑 → 變成「在 X 類問題上踩過多次」
  - 模式類條目保留，事件類條目可濃縮

太多紀錄反而失去用處。寧可少紀，不要多紀。
但「太遠」≠「不重要」，濃縮後仍要保留下次能用到的資訊。

---

## 紀錄格式範本

每個 `notes.md` 大致結構：

```markdown
# {Context Name} Notes

## Recent (近期，< 1 個月，原始紀錄)
- [YYYY-MM-DD] 極簡單行紀錄
- [YYYY-MM-DD] 極簡單行紀錄

## Patterns (重複模式)
- 觀察到的習慣或偏好

## Condensed (濃縮歷史，> 1 個月，已合併成模式)
- [YYYY-MM] X 類事件多次發生（具體 N 次）
- [YYYY-Q1] Y 階段主要學會 / 處理過的事
- [YYYY-H1] Z 領域有過幾次經驗

## To use next time (待用)
- 下次該語境互動時要注意 / 提及的事
```

具體欄位依語境而異，詳見各 `notes.md`。

## 寫法範例

### ❌ 過詳細
> [2026-05-21] 用戶問了關於量子運算的問題，他想知道 Grover's algorithm 為什麼能將時間複雜度從 O(N) 降到 O(√N)。我解釋了反射操作和振幅放大的概念，他似乎理解了。但對於 oracle 的部分還不太清楚，需要下次補充說明。

### ✅ 最小紀錄
> [2026-05-21] 量子: Grover ok, oracle 還要補

---

## 濃縮範例（事件 → 模式）

### Recent（保持原始）
```
- [2026-05-21] 量子: Grover ok, oracle 還要補
- [2026-05-18] 量子: 疊加態幾何直覺建立（Bloch sphere）
- [2026-05-15] 量子: Hadamard / CNOT 邏輯閘 ok
- [2026-05-10] 量子: 線性代數複習過 eigenvalue / eigenvector
```

### Condensed（1+ 個月後濃縮成模式）
```
- [2026-05] 量子運算基礎建立（疊加、邏輯閘、Grover ok；oracle、量子演算法數學原理還要補）
```

四條近期紀錄濃縮成一條模式描述。**資訊保留：知道用戶該段時間學會了什麼、還沒學會什麼**。
細節（哪一天學什麼）捨棄。

---

## 何時觸發濃縮

- `notes.md` 行數 > 50
- 寫入新條目時，發現舊條目可合併
- 月底 / 季末，可主動檢查 Recent 區是否有可移到 Condensed 的

濃縮不一定要立刻做。如果某個近期事件還在被頻繁呼應（例：教學中正在反覆使用），可以晚點再濃縮。

---

## 隱私 / 同意

- 用戶明確說「別記這個」→ 不記、刪掉相關條目
- 涉及他人隱私（用戶提到的朋友、家人）→ 只記跟用戶習慣相關的部分
- 涉及敏感事件（疾病、感情、財務）→ 只記用戶希望被怎麼對待的模式，不記細節
