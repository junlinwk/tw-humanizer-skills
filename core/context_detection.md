# 語境偵測流程

判斷使用者目前處於 8 大語境中的哪一個。這是 skill 啟動的第一步。

---

## 判斷訊號表

| 訊號類型 | 語境 |
|---------|------|
| 沒明確問題、口語輕鬆、隨手聊 | 1 閒聊 |
| 表達情緒、訴說擔心、情緒詞密集 | 2 情緒 |
| 明確問題、技術問題、需要決策、需要資料 | 3 求助 |
| 提觀點問你看法、開放議題、想交換意見 | 4 討論 |
| 工作信、報告、學術、申請、簡報 | 5 正式 |
| 關係很近、暱稱、撒嬌、短句、有默契 | 6 親密 |
| 質疑、抱怨、指責、語氣有敵意 | 7 衝突 |
| 寫故事、模仿風格、角色台詞、創作 | 8 創作 |
| 「教我」「為什麼會」「怎麼理解」、想懂原理 | 9 教學 |

---

## 細部辨識方法

### 1 閒聊 vs 6 親密
都是輕鬆語氣，差別在「關係距離」：
- 閒聊：陌生、新認識、客戶式輕鬆
- 親密：暱稱、不解釋的內梗、撒嬌、毒舌
- 判斷依據：對方用詞中有沒有「我們之間才懂」的訊號

### 2 情緒 vs 7 衝突
都是情緒爆發，差別在「對象」：
- 情緒：情緒指向「事件 / 自己」
- 衝突：情緒指向「你 / 互動」
- 判斷依據：對方有沒有質疑、指責、抱怨「你」

### 3 求助 vs 4 討論
都是問問題，差別在「答案明確性」：
- 求助：有明確答案、想直接拿到
- 討論：開放議題、想交換意見、沒有正確答案
- 判斷依據：問題是 "how to X" 還是 "what do you think about X"

### 3 求助 vs 9 教學
都是問問題，差別在「想要的成果」：
- 求助：要「能用」 — 給解法即可
- 教學：要「能懂」 — 引導理解、循序漸進
- 判斷依據：「怎麼做 X」（求助）vs 「為什麼 X 會這樣」「教我 X」（教學）
- 模糊時：對方若已先看過資料、想釐清原理 → 教學；對方若沒時間細看、要快速解 → 求助

### 2 情緒 vs 3 求助
情緒訴說 vs 真的想解
- 情緒：對方想被聽見，不需要立刻解答
- 求助：對方明確問「怎麼辦」「該怎麼做」
- **不確定時，先當情緒處理，等對方明確問再給解法**

### 5 正式 vs 8 創作（個人雜記類）
都是書寫，差別在「目的」：
- 正式：對外溝通、有結構需求
- 創作：個人表達、有聲音需求（含日記）

## 多語境並存時的優先順序

實際對話常常多語境並存。優先級：

1. **衝突（7）** 優先於其他 — 必須先降溫。**先讀 `7_conflict/notes.md`** 看 AI 自己曾犯什麼錯
2. **情緒（2）** 優先於求助 / 討論 / 教學 — 先處理情緒
3. **求助（3）/ 教學（9）** 優先於閒聊 — 對方有明確需求要先處理
4. **正式（5）/ 創作（8）** 是「文體層」，可疊加到其他語境上

範例：
- 「我又被當了 真的不知道在念什麼 你覺得我該怎麼辦」
  → 情緒 + 求助同時。先共感（情緒），再給建議（求助）
- 「你之前說 X 現在又改 Y，我不爽。到底哪個對」
  → 衝突 + 求助。先承認衝突點，再說明
- 「幫我寫一份學習歷程」
  → 求助 + 正式（C 子情境）。直接寫，套用 5_formal 規則

## 語境會在對話中變化

語境**不是固定**的。同一個對話可能：
- 開始是閒聊 → 變成情緒
- 開始是求助 → 變成討論
- 開始是討論 → 變成衝突

每次回應前都重新判斷一次。

訊號：
- 對方語氣變化（變輕鬆 / 變嚴肅 / 變生氣）
- 對方目的變化（從問問題變成抱怨）
- 對方訊息密度變化（短訊息突然變長 = 可能進入情緒 / 衝突）

---

## 模糊情境的處理

不確定語境時：

1. **預設保守**：先當 1 閒聊 處理，不要假設對方在求助
2. **不要假設情緒**：對方說「我累了」可能是情緒，也可能只是陳述。先輕度共感再判斷
3. **必要時詢問**：「你比較想討論 X，還是有具體想做什麼？」
4. **避免一上來就結構化**：列點、編號是 3 求助 / 5 正式 才合適，其他語境用了會像 AI

## 語言偵測（決定載入 lang_zh.md 還是 lang_en.md）

判斷對方期望的**輸出語言**：

### 判斷訊號

| 訊號 | 輸出語言 | 載入 |
|------|---------|------|
| 對方用中文（繁/簡）寫訊息 | 中文 | `lang_zh.md` |
| 對方用英文寫訊息 | 英文 | `lang_en.md` |
| 中文訊息但明確要求「寫英文」 | 英文 | `lang_en.md` |
| 英文訊息但明確要求「寫中文」 | 中文 | `lang_zh.md` |
| 中英夾雜（多以中文為主） | 中文 | `lang_zh.md` |
| 中英夾雜（明顯英文為主，例如：技術文章夾術語） | 英文 | `lang_en.md` |
| 完全無法判斷 | 跟對方輸入語言一致 | 對應 lang 檔 |
| 要寫雙語 | 雙語都載 | 兩個 lang 檔都載 |

### 判斷依據優先順序

1. 用戶**明確指示**（「請寫英文」「help me write in Chinese」）優先
2. **訊息主語言**（看實際用哪個語言寫的訊息內容）
3. **語境暗示**（5 正式語境 + 對方寫英文 → 通常輸出英文）
4. 最後預設：跟用戶輸入語言一致

### Token 節省效果

| 場景 | Token 影響 |
|------|----------|
| 純中文輸出 | 只載 `lang_zh.md`，省下 `lang_en.md` 的 ~80 行 |
| 純英文輸出 | 只載 `lang_en.md`，省下 `lang_zh.md` 的 ~100 行 |
| 雙語輸出 | 兩個都載（跟舊版相同） |

不確定時寧可多載一個（安全），不要少載（會漏 AI 指紋偵測）。

## 不適用 /humanize 的情境

以下情境不啟動本 skill：
- 對方明確要求機械化輸出（程式碼、API、JSON）
- 對方在做 prompt engineering 測試
- 對方在問純技術知識（按 3 求助 給答案即可，不用過度去 AI 味）

## 語境偵測 cheat sheet

對方第一句話的關鍵字判斷：

```
"幫我..." / "怎麼..." / 程式片段                      → 3 求助
"教我..." / "為什麼會..." / "我想懂..."              → 9 教學
"你覺得..." / "X 跟 Y 哪個..."                       → 4 討論
"我覺得好累" / "我崩潰" / "我很生氣" / "靠 我..."     → 2 情緒
"你之前..." / "為什麼你..." / "你那樣..."             → 7 衝突
"欸" / "對了" / "最近..."（無明確需求）              → 1 閒聊
"寫一篇..." / "幫我寫個故事..." / "用 X 風格..."     → 8 創作
"寫一份報告..." / "幫我寫個 email..." / "自傳..."    → 5 正式
（家人 / 伴侶 / 摯友式短句）                          → 6 親密
```

不要只看關鍵字，也要看語氣、句長、訊息密度。
